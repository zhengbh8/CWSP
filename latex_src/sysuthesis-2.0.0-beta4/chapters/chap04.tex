\chapter{数值实验与结果分析}

为了全面验证本文提出的基于线图映射的非加性最短路径算法（CWSP）的正确性以及面向 GPU 的并行优化方案的有效性，本章将开展多组定性与定量的对比实验.通过自建微观场景与真实大规模网络数据集，分别从算法的路径求解可行性和并行计算性能两个维度进行分析.

\section{实验准备}

\subsection{实验软硬件环境}
本章相关的串行与并行实验均在同一台计算节点上完成，以保证实验误差降至最低.硬件平台配置为：处理器方面，搭载了 \textbf{Intel(R) Xeon(R) CPU E5-2680 v4 @ 2.40GHz}；在并行加速方面，使用了 \textbf{NVIDIA GeForce RTX 3090 GPU}（24GB 显存）.针对不同算法的具体实现，软件环境配置如下：
\begin{itemize}
    \item \textbf{操作系统}：Ubuntu 20.04 LTS (64-bit).
    \item \textbf{开发语言与标准}：串行基准算法以及相应的预处理脚本基于 Python 3.10 及 NetworkX 库实现；GPU 并行算法基于 C++17 与 CUDA 11.8 框架编写.
    \item \textbf{编译环境}：使用 gcc/g++ 11.3 编译器以及 nvcc 编译器，并开起了 -O3 级别的深度优化.
\end{itemize}

\subsection{实验数据集说明}
为了客观地评估本文算法的计算性能，实验采用了两类数据集，详见以下说明：
\begin{itemize}
    \item \textbf{实体微观路网数据：} 取自迈阿密国际机场（MIA）的真实滑行道拓扑数据，包含数百个节点与物理交叉口.该路网用于验证算法能否在面临大夹角锐角转弯等非加性约束时，正确输出无碰撞的可行路径.
    \item \textbf{大规模网络数据集：} 为考察并行算法在图规模不断增加时的加速表现，实验引入或生成了多组处于不同数量级的大规模网络.图中顶点数记为 $n$，边数记为 $m$，通过赋予边与节点不同的权值和非加性转弯惩罚，用于极限压力测试.
\end{itemize}

\section{实验设计}

\subsection{基准算法对比设置}
为了多维度衡量各类算法，实验选取了以下三组实现基准作为对照模型：
\begin{enumerate}
    \item \textbf{传统 Dijkstra 算法（基准线）：} 最早的未考虑非加性转弯惩罚的贪心最短路算法，作为考察由于未考虑约束导致其合法率下降的参照物.
    \item \textbf{串行线图 CWSP 算法（本文理论）：} 基于 Python 及纯 CPU 实现的线图转换与松弛算法.虽然兼顾了多约束惩罚，但在庞大节点数下可能存在极长的运行耗时，用以验证解的正确性.
    \item \textbf{基于 GPU 并行的 CWSP 算法（本文核心）：} 基于 CUDA 并行对线图转化与 $\Delta$-Stepping 算法结构进行加速的优化实现，并在相同数据集上参与性能对比.
\end{enumerate}

\subsection{性能评价指标}
实验选用以下三个维度作为评价算法好坏的指标：
\begin{enumerate}
    \item \textbf{路径可行性（Success Rate）：} 代表算法求出的源节点至目标节点之间距离是否触发了非加性约束的高昂惩罚，若代价变为 $+\infty$ 则表示寻路失效，反之则成功.
    \item \textbf{运行时间（Running Time, 毫秒/秒）：} 在同等输入环境下算法求出结果的绝对计算耗时（为减少误差，实验结果均基于五次重复实验得出平均值）.
    \item \textbf{加速比（Speedup）：} 用于衡量并行优化带来的提升幅度，其计算公式为：$$ Speedup = \frac{T_{serial}}{T_{parallel}} $$ 其中 $T_{serial}$ 为对应的串行执行时间，$T_{parallel}$ 为 GPU 并行条件下的执行时间.
\end{enumerate}

\end{itemize}


\section{GPU并行算法与串行算法的性能对比与加速比分析}

前文实验表明线图 CWSP 算法虽然能有效解决非加性最短路径问题，但由于线图转换（$L(G)$）会引入平方级别的图规模增长，给传统串行 CPU 计算带来了极为沉重的耗时压力.因此，本节将通过不同规模的数据测试，严格按照算法流水线的执行顺序，结合第三章提出的三项核心并行优化策略逐一验证加速效率，并最终评估算法规模化应用时的总体加速表现.

\subsection{线图拓扑并行重构的加速比分析}
本节对应第三章 3.3.1 节介绍的线图拓扑并行构建策略.在这里我们将主要讨论单纯剥离出“边转点、伴随边映射”图结构替换步骤时，基于前缀和（Prefix Sum）的 GPU 并发无锁写入策略相比于 CPU 动态申请内存建图所带来的加速效果.

在实验中，我们预设了包含不同节点规模的稠密网络集.通过严密的计时分析统计发现，在传统的串行 CPU 计算中，由于每条边的引出后继边数量不一，动态延展替代图规模不仅会造成极高的内存碎片化，也会由于频繁的开辟内存导致耗时呈几何级数增长.相对而言，利用 GPU 一维内核配合高效并行前缀和计算预先扫描出度，并在第二步实现完全无锁的 CSR 并发写入操作，极大地平抑了这种计算开销.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.88\textwidth]{figures/exp4_4_1_topology_speedup.pdf}
    \caption{线图拓扑并行重构阶段的加速比（CPU/GPU）随原图边数 $m$ 的变化}
    \label{fig:exp_phase1_topology}
\end{figure}

如图~\ref{fig:exp_phase1_topology} 所示，在小规模图（如 $m\le 6{,}240$）下，GPU 由于内核启动与并行扫描的固定开销占比更高，整体加速比仍小于 1；随着图规模增大，CPU 侧线图拓扑构建耗时近似线性增长，而 GPU 端两阶段（count+scan+fill）并发写入的耗时增长较缓，因而加速比快速提升.在 $m=25{,}280$（$80\times 80$ 网格）时加速比约为 $3.43\times$，在 $m=39{,}600$（$100\times 100$ 网格）时可达到约 $4.99\times$；在真实 MIA 数据集（$m=11{,}584$）上亦获得约 $1.77\times$ 的阶段加速.该结果表明，通过前缀和预分配并配合无锁 CSR 填充，可以有效削弱 CPU 端频繁动态扩容造成的开销，并为后续权重计算与并行寻优阶段提供稳定的高吞吐图结构基础.

\subsection{条件权重并行计算的加速比分析}
本节对应第三章 3.3.2 节所提的线图条件权重并行计算模块.线图中的伴随边权值需要读取原图两条连贯边的角度以计算非加性惩罚.得益于线图结构重构已经完成，所有的权重计算彼此独立，本节将通过实验测试 GPU 海量线程并发执行夹角计算与惩罚判定时的极速吞吐表现.

在并行设计中，原网络中的动态代价判断逻辑涉及向量点积以及多分支的物理阈值判定（如过滤非法夹角）.该过程通过 SIMT 架构被完美映射到设备的计算单元中.针对分支发散可能引起的性能衰减，我们实施了内部谓词指令替换（Predication）等并发约束优化，以保证内存聚合访问效率.

\input{figures/tab_exp_phase2_weight.tex}

表~\ref{tab:exp_phase2_weight} 给出了不同线图伴随边规模 $|E_H|$ 下的条件权重计算耗时.可以观察到：当 $|E_H|$ 从 $1.0\times 10^5$ 增长到 $5.0\times 10^6$ 时，CPU 顺序解析耗时由约 $0.70\,\text{ms}$ 增长到约 $32.49\,\text{ms}$；GPU 端即使采用朴素分支实现也能将耗时稳定控制在 $0.007\sim0.103\,\text{ms}$ 区间，而通过 SIMT 谓词对齐后进一步降低到 $0.006\sim0.095\,\text{ms}$，对应的阶段加速比约为 $110\times$ 到 $353\times$.这说明在线图权重计算阶段，将分支判定与夹角（方向）计算进行结构化改写、减少线程束内分歧，能够显著提升吞吐并降低尾部延迟，从而有效避免该阶段在大规模线图上成为性能瓶颈.

\subsection{并行寻优算法 (\texorpdfstring{$\Delta$}{Delta}-Stepping) 性能分析}

在进行并行寻优替代方案的性能评估之前，有必要先对经典的单源最短路径算法在并行化潜力上的差异进行理论对比.传统 Dijkstra 算法不仅是串行计算的标杆基准，其基于全序优先队列（Priority Queue）的设计有效保障了最少的全局边松弛次数.然而由于其强顺序依赖性（Sequential Dependency），Dijkstra 算法在每一次迭代中仅能弹出一个局部距离最近的未访问顶点执行松弛，这种内在属性极大地制约了其在以大规模单指令多线程（SIMT）为核心的 GPU 计算环境上的并行扩展性.相比之下，本研究所采用的 $\Delta$-Stepping 算法通过引入分级“桶（Bucket）”机制，改变了松弛波前的调度范式.它允许将探寻距离落在同一 $[i\Delta, (i+1)\Delta)$ 区间内的多个波前活跃节点暂存入同一个当前桶中，并一次性予以无序的并发松弛.借由这种桶式并行机制，$\Delta$-Stepping 算法在维持了趋近于 Dijkstra 高收敛精度的同时，充盈了并发延展特性，有效规避了串行优先队列的严格读写依赖瓶颈.

为了全面评估 $\Delta$-Stepping 算法在 GPU 并行环境下的综合性能表现，并直观量化上述机制差异带来的计算收益，本节首先对 $\Delta$-Stepping 算法与传统 Dijkstra 算法进行了多维度的实验量化比对，随后重点剖析了核心跨步参数对于该算法深层次演化的敏感度影响.

在效率对比实验中，我们在不同规模的网格图上构建对应线图，并在该线图上分别运行 CPU 串行优先队列 Dijkstra 与 GPU 桶式 $\Delta$-Stepping 算法.为与本节后续的参数敏感性分析保持一致，桶宽参数取 $\Delta=35$；线图边权由“基础边权 + 转向惩罚”构成（基础边权取 $1\sim 5$，转向惩罚取 10），并确保满足 $w\le\Delta$ 以便桶内闭包松弛能够正确收敛.各规模点位均重复运行 3 次取均值，结果如表~\ref{tab:exp_phase3_dijkstra_vs_delta} 所示.

\input{figures/tab_exp_phase3_dijkstra_vs_delta.tex}

从表~\ref{tab:exp_phase3_dijkstra_vs_delta} 可以观察到：随着图规模增大，CPU Dijkstra 的全局最小堆维护与大量串行弹出操作逐渐成为主导开销，而 GPU 端 $\Delta$-Stepping 算法能将同一桶内的大量松弛操作并行展开，从而加速比从小规模的约 $1.36\times$ 提升到大规模的约 $4.78\times$，体现出其在大规模图上的并行收益.

在完成端到端效率对比后，我们进一步关注核心参数 $\Delta$ 对 GPU 侧松弛阶段的敏感性影响.具体而言，我们在固定数据集（本章前述网格图）上线图拓扑已完成构建的前提下，使用“松弛 + 桶同步”代理基准对 $\Delta$ 做 sweep：
(1) 将距离范围离散为固定的桶跨度（bucket range），并据此令桶轮数近似为 $\text{steps}\approx\lfloor\text{range}/\Delta\rfloor$；
(2) 每轮从当前桶中抽取与 $\Delta$ 成比例的活跃规模进行并发松弛；
(3) 每轮松弛后施加一次全局同步屏障以刻画桶切换（barrier）开销，同时在 $\Delta$ 较大时引入更强的原子争用与冗余松弛工作以模拟“桶过宽”带来的并发冲突.
为降低 GPU 计时抖动，各 $\Delta$ 点位均重复运行 5 次取均值.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.8\textwidth]{figures/delta_ucurve.png}
    \caption{$\Delta$ 参数大小对算法收敛性能的极深敏感度影响}
    \label{fig:exp_phase3_delta}
\end{figure}

从图~\ref{fig:exp_phase3_delta} 的参数敏感性变化趋势中可以观察到，在 $\Delta$ 参数值选取的两级极端情况下，均出现了极为明显的性能衰退现象：
当 $\Delta$ 取值过小（如图左侧区域所示）时，受限于狭窄的处理跨度，单次派发至 GPU 并发处理核心内的顶点（或边）数量急剧减缩，且大多时间消耗在处理桶列更替.此时该算法在执行结构上近似退化为每次进行单节点探索的 Dijkstra 连续单步寻路.高密度的层级边界越替伴随着频繁发起的全局设备层同步屏障（Barrier Synchronization），引发了难以忽视的时间延迟与挂起额外开销，导致总寻得耗时大幅攀升.
相反，当 $\Delta$ 步长取值被分配得过大（如图右侧区域扩展所示），过宽的处理区界将众多本不在同一收敛前沿等级内的节点囊括进同一并发桶中执行.这种同层域中极其狂放的漫灌松弛会使得核心计算线程在争夺全局内存或寻优回写时，触发极为高频的原子争用冲突（Atomic Contention），并连带导致大量远期顶点过早唤醒进而产生冗余修正.在极大步长下算法倾向退化为无差别的 Bellman-Ford 特征，同样丧失了并行收敛准度效率.

综合上述两类开销的对抗关系，图~\ref{fig:exp_phase3_delta} 呈现出典型的“先降后升”的敏感性曲线：在 $\Delta$ 从 5 增加到 35 的区间内，总耗时随桶轮数减少而快速下降；当 $\Delta$ 继续增大时，尽管同步轮次进一步降低，但由原子争用与冗余松弛引入的单轮代价上升逐步占据主导，从而使总耗时明显回升.对于本文所用网格图规模与 GPU 架构条件，较优的经验区间可由曲线最低点附近估计为 $\Delta\approx 35\sim 45$，本章其余实验亦采用 $\Delta=35$ 作为默认配置.

结合表~\ref{tab:exp_phase4_overall_breakdown} 的分解结果可进一步看出：在 CPU 端，随着规模增长，“寻优”阶段（优先队列维护与串行弹出）增长更快并逐步占据总耗时主导；而在 GPU 端，权重计算与拓扑构建阶段的耗时占比相对更低，总体主要由 $\Delta$-Stepping 算法的桶式松弛与必要的数据传输构成，这也解释了端到端曲线在大规模区间仍能保持稳定加速比.

以两端点位为例：在 $100\times100$ 网格对应的线图规模 $|V_H|=39{,}600, |E_H|=157{,}208$ 时，CPU 端到端总耗时为 $8.523\,\text{ms}$，GPU 端为 $4.555\,\text{ms}$，总体加速比约为 $1.87\times$；当规模增至 $300\times300$（$|V_H|=358{,}800, |E_H|=1{,}431{,}608$）时，CPU 总耗时上升至 $84.283\,\text{ms}$，GPU 为 $17.276\,\text{ms}$，加速比提升到约 $4.88\times$.从阶段占比看，CPU 端“寻优”阶段在两端点位分别约占总耗时的 $83.7\%$ 与 $84.8\%$，说明串行优先队列维护逐步成为主导瓶颈；GPU 端则主要由“寻优+传输”构成（约 $98.8\%\sim98.9\%$），而拓扑构建与权重计算合计占比均低于 $1.3\%$，从而使总体端到端性能随规模增长保持较好的可扩展性.

\subsection{不同历史阶数 $k$ 下的三阶段耗时分布与加速趋势}

前述 4.4.1\textasciitilde 4.4.4 的并行加速分析建立在“仅依赖相邻两条连贯边”的场景之上.为进一步评估本文流水线在更一般的\emph{有限阶历史依赖}情形下的可扩展性，本小节固定同一组原图与惩罚设置，仅改变历史阶数 $k$，并严格沿用三阶段计时口径：\emph{阶段1}为替代图（状态展开后图）拓扑构建，\emph{阶段2}为条件权重计算（代价显式依赖最近 $k$ 步方向序列），\emph{阶段3}为最短路寻优（CPU 端 Dijkstra / GPU 端 $\Delta$-Stepping 算法）.

为更充分暴露“高阶历史状态展开”带来的构图压力，本节采用更稠密的网格原图：在 $40\times 40$ 基础上允许沿四邻域方向以步长 $1\sim 2$ 连边（即每个节点最多 8 条出边），记为 dataset: \texttt{grid\_40x40\_step2}，并取默认 $\Delta=35$.在资源允许的前提下对 $k$ 进行扩大测试；当 $k\ge 6$ 时替代图规模增长过快，会触发显存分配失败（GPU out-of-memory），因此本节报告可稳定复现的 $k\in\{1,2,3,4,5\}$ 结果.

为刻画“历史状态空间膨胀”带来的规模变化，表~\ref{tab:exp_kadditive_scale} 给出了状态展开后替代图的顶点与边规模 $|V_H|,|E_H|$.可以观察到：当 $k$ 从 1 增至 5 时，$|V_H|$ 由 12{,}320 增长到 45{,}624{,}760，$|E_H|$ 由 95{,}592 增长到 357{,}975{,}784，呈现出典型的指数式膨胀趋势，这将直接推高阶段1/2 的构建与加权开销.

进一步对比各 $k$ 点位的相对增幅可发现，替代图规模在每提升一个历史阶数时均出现近似倍数扩张：相较于 $k=1$，当 $k=2$ 时 $|V_H|$ 与 $|E_H|$ 约增长 $7.76\times$ 与 $7.79\times$；当 $k=3$ 时分别增长到约 $60.47\times$ 与 $60.93\times$；当 $k=4$ 时分别达到约 $472.74\times$ 与 $477.29\times$；当 $k=5$ 时进一步膨胀至约 $3703.31\times$ 与 $3744.83\times$.这说明在固定原图与连边规则下，$k$ 的增加将通过“状态展开 + 连续线图变换”的链式作用快速放大可达状态数，从而驱动替代图在顶点与边两个维度同时爆炸式增长.

这种规模变化与三阶段耗时的增长趋势具有直接对应关系：阶段1需要对每一层线图进行出度统计、前缀和扫描并写入 CSR 结构，其总体工作量与 $|E_H|$ 同阶；阶段2需要对替代图的每条边并行/串行计算条件权重，其总体工作量同样随 $|E_H|$ 增长；阶段3的寻优复杂度则与 $|V_H|$ 与 $|E_H|$ 同时相关（CPU 端优先队列维护的顺序依赖在规模膨胀后被进一步放大）.因此，当 $k$ 增大时，三个阶段都会受到“规模膨胀”的系统性影响，但其增长速度与瓶颈位置将由具体实现的并行度与同步/调度开销共同决定.

值得强调的是，本实验在 $k=6$ 时出现 GPU out-of-memory，并非异常噪声，而是上述“指数式膨胀”的自然后果：当 $k=5$ 时替代图已达到 $|V_H|\approx 4.56\times 10^7$、$|E_H|\approx 3.58\times 10^8$ 的规模，阶段1需要在显存中同时容纳多组 CSR 数组（行指针、列索引、计数/扫描缓冲、状态与映射等），继续提升到更高 $k$ 将迅速超出单卡显存上限，从工程角度反证了高阶历史依赖场景下“替代图生成与存储”将成为最先触碰资源上限的关键挑战.

表~\ref{tab:exp_kadditive_timing} 与图~\ref{fig:exp_kadditive_breakdown_cpu}、图~\ref{fig:exp_kadditive_breakdown_gpu} 分别给出了 CPU 与 GPU 在不同 $k$ 下的三阶段耗时分布.总体趋势表现为：随着 $k$ 增大，CPU 端总耗时呈现爆炸式上升，GPU 端亦显著增长但斜率更小.以端到端总耗时为例，CPU 侧从 $k=1$ 的 $2.883\,\text{ms}$ 增至 $k=5$ 的 $19.045\,\text{s}$；GPU 侧从 $1.258\,\text{ms}$ 增至 $124.939\,\text{ms}$.对应的端到端加速比由 $2.291\times$ 提升到 $152.436\times$（见表~\ref{tab:exp_kadditive_timing} 与图~\ref{fig:exp_kadditive_speedup}）.

从“GPU 相比 CPU 的分阶段提升”来看，表~\ref{tab:exp_kadditive_timing} 与图~\ref{fig:exp_kadditive_speedup} 给出的结果呈现出清晰的随 $k$ 增大而增强的趋势：
(1)\,\textbf{阶段1（替代图拓扑构建）}的加速比从 $k=1$ 的约 $4.13\times$ 增长到 $k=5$ 的约 $48.90\times$.这是由于阶段1本质上属于规则化的“计数+扫描+写入”流水线，GPU 并行度随 $|E_H|$ 增大而更充分被填满，同时避免了 CPU 端动态扩容与串行写入带来的高额开销.
(2)\,\textbf{阶段2（条件加权）}加速比提升更为显著：从 $k=1$ 的约 $10.97\times$ 快速增长到 $k=3$ 的约 $264.67\times$，并在 $k=4$ 与 $k=5$ 维持在约 $266\times$ 的高位.这表明在替代图边规模增大后，条件权重计算几乎完全由数据并行的边级 kernel 主导，GPU 能以接近饱和的吞吐持续摊薄控制分支与访存代价.
(3)\,\textbf{阶段3（最短路寻优）}同样随着 $k$ 增大表现出更高的相对优势：从 $k=1$ 的 $1.95\times$ 增长到 $k=5$ 的 $180.62\times$.其原因在于规模膨胀下 CPU 侧优先队列维护与全序弹出松弛的顺序依赖被极度放大，而 GPU 侧 $\Delta$-Stepping 算法可将同桶内的大量松弛并行化，从而在大规模区间显著抑制阶段3 的增长斜率.

综合三阶段后，\textbf{端到端总加速比}由 $k=1$ 的 $2.29\times$ 单调提升到 $k=5$ 的 $152.44\times$，说明尽管高阶历史依赖会同时放大三阶段的工作量，但 GPU 侧在拓扑构建、条件加权与并行寻优三个环节均能随规模增长持续释放并行收益，从而在高阶 $k$ 区间取得更显著的端到端优势.

从阶段占比进一步分析可得：
在 CPU 端，尽管阶段1/2 的绝对耗时随 $k$ 显著增长（例如 $k=5$ 时阶段1/2 分别达到 $1.566\,\text{s}$ 与 $2.163\,\text{s}$），但由于本基准的阶段3采用完整单源最短路（需遍历全图并维护优先队列），阶段3 仍保持主导（$k=5$ 时阶段3 为 $15.316\,\text{s}$，约占总耗时的 $80.4\%$）.这说明在“高阶状态展开 + 全图 SSSP”的组合下，瓶颈并不会简单地完全前移到构图阶段，而是呈现为\emph{阶段1/2 与阶段3 同时被状态膨胀放大}的现象.

在 GPU 端，阶段2（权重计算）依旧保持高吞吐并发优势（$k=5$ 时仅 $8.119\,\text{ms}$），而阶段1（拓扑构建与状态展开）占比明显抬升（$k=5$ 时约占 $25.6\%$，已超过阶段2），阶段3 仍为主要组成部分（约 $67.9\%$）.因此，本节的实验结论可以更精确地表述为：\emph{随着 $k$ 增大，阶段1/2 的构建与加权代价确实显著增长并在 GPU 侧更早“显性化”，但在完整\allowbreak SSSP 口径下阶段3 仍可能保持主导}.当进一步扩大 $k$ 时替代图规模会迅速超出单卡显存承载能力（本实验在 $k=6$ 即出现 OOM），这从工程角度反证了高阶历史依赖的主要挑战之一正是阶段1所对应的结构生成与存储压力.

\section{本章小结}

本章围绕“路径依赖型（有限阶历史依赖）最短路径问题”的可解性与可扩展性，使用微观机场路网与多组可控的大规模网络数据，系统验证了本文提出的 CWSP 框架及其 GPU 并行化实现.

首先，在真实 MIA 微观滑行道场景中，实验表明传统最短路径算法在包含锐角转弯惩罚等历史依赖约束时存在显著失效率，而线图映射后的 CWSP 能稳定输出合法可行路径，并在传统算法尚未失效的安全路段保持代价值一致，从而从“正确性/可行性”维度验证了拓扑替代与条件加权思想的有效性.

其次，在性能层面，本章严格按照 CWSP 流水线的执行顺序，将端到端计算拆解为三阶段并分别量化加速收益：在线图拓扑构建阶段，GPU 基于前缀和的预分配与无锁 CSR 写入在图规模增大时展现出稳定的吞吐优势；在条件加权阶段，SIMT 并行与分支规整使得 GPU 能将边级代价计算的开销显著压缩；在寻优阶段，桶式 $\Delta$-Stepping 算法通过波前并行松弛缓解了 Dijkstra 全序优先队列的顺序依赖瓶颈，从而在大规模线图上获得可观的阶段加速与端到端收益.

最后，为检验更一般的高阶历史依赖情形，本章补充了不同历史阶数 $k$ 的扩展实验（4.4.5）.结果显示，随着 $k$ 增大，替代图规模 $|V_H|$ 与 $|E_H|$ 呈指数式膨胀，并同步推高三阶段耗时；同时 GPU 在拓扑构建、条件加权与并行寻优三个环节的加速比均随规模增长而增强，端到端加速比在较高 $k$ 区间进一步放大.需要指出的是，当 $k$ 继续增大时，替代图生成与存储会率先触碰资源上限（本实验在 $k=6$ 出现 GPU out-of-memory），这从工程角度揭示了高阶历史依赖场景下的核心挑战之一：如何在保证等价性的前提下抑制状态空间膨胀带来的结构化内存压力.
